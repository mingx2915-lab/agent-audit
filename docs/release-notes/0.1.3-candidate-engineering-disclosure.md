# AgentAudit 0.1.3 candidate — Engineering and dependency disclosure

**Status:** Candidate source, not a published release. The Windows and Linux installers, source archive, checksum manifest, signatures, and exact-commit Actions results must be aligned before publication. The final run links and artifact hashes belong in the GitHub Release description and signed checksum manifest.

## Validation boundary

- The quality matrix tests the checked-in Python, Web, Desktop and Rust commands on Windows 2022 and Ubuntu 24.04 runners. A passing matrix does not itself verify installation.
- The Windows release workflow builds an NSIS installer, installs it in an isolated current-user directory, exercises two Desktop/Sidecar start-stop rounds and one controlled crash recovery, and checks uninstall. An independent clean Windows PC and complete visual flow remain unverified.
- The Linux release workflow builds AppImage and `.deb`, checks installed artifact structure and drives the real GTK file chooser in both packaged programs under an isolated Xvfb session. The `.deb` check uses its extracted program; installation on another Debian desktop remains unverified. The file chooser uses a non-secret fixture and does not verify live model inference.
- The supply-chain workflow remains enabled and fails its policy gate while unresolved findings remain. A failing supply-chain result must not be described as all-green CI.

## Open RustSec findings

The current locked Cargo inventory has eight pending advisories. Seven describe unmaintained transitive dependencies (`proc-macro-error 1.0.4`, `ttf-parser 0.25.1`, and five `unic-* 0.9.0` crates); one describes unsound `VariantStrIter` APIs in `glib 0.18.5` (RUSTSEC-2024-0429). These are unresolved dependency findings, not eight confirmed exploitable application vulnerabilities. The scanner is not disabled and these items are not silently accepted or allowlisted. The affected dependency paths, reachability assessment, update constraints and individual advisory identifiers are recorded in [the prior candidate disclosure](0.1.2-candidate-engineering-disclosure.md). A fresh scan and its actual status must accompany this candidate's final commit.
