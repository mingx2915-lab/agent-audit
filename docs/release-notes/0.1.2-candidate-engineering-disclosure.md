## Why these findings remain

- The Tauri stack resolves to Tauri `2.11.5`, Wry `0.55.1`, GTK `0.18.2`, and GLib `0.18.5`. Wry's [GTK4/WebKit6 migration pull request](https://github.com/tauri-apps/wry/pull/1767) is still open and includes API and system-package changes. The separate [GTK 0.19 update](https://github.com/tauri-apps/wry/pull/1843) is still a draft, waits on upstream dependencies, and raises its MSRV to Rust 1.92; this project currently tests Rust 1.88. Neither change is a released compatible update for this candidate.
- Tauri's current locked `tauri-utils 2.9.3` still selects `urlpattern 0.3.0`; overriding that dependency alone would cross its pre-1.0 compatibility boundary.
- `glib`'s unsoundness advisory lists `>=0.20.0` as patched, but the current GTK3/Wry stack pins GLib 0.18.5; the application's direct reachability assessment is recorded above ([RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429)).
- `ttf-parser` has no patched version in its current RustSec advisory; the application uses it through its PDF text-import path ([RUSTSEC-2026-0192](https://rustsec.org/advisories/RUSTSEC-2026-0192)).
- An online `cargo-audit` refresh was attempted locally but could not fetch `https://github.com/RustSec/advisory-db.git`. The findings remain `in_progress`; the supply-chain workflow and its failure policy were not disabled or allowlisted. Refresh the scan artifact on GitHub before publishing.
