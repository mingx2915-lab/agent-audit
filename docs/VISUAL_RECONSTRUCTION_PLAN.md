# 知盾 AgentAudit 品牌视觉恢复与界面清晰化重构计划

> 状态：Proposed，等待确认后执行  
> 建议后续功能编号：F-063 品牌视觉恢复与比赛可读性重构  
> 本文只定义视觉与前端重构方案，不代表功能已经开始或完成；确认执行后，应先创建 F-063 功能文档，并同步 `docs/STATUS.md` 与 `docs/FEATURES.md`。

## 1. 结论

本次不做“回滚到旧版”，也不继续沿当前白色扁平界面做零散美化。

采用以下组合路线：

- 以旧版的品牌色、深色证据舞台、状态插图和层次感作为视觉基础；
- 保留当前版本已经改善的中文业务表达、四工作区导航、首用路径、攻击链等高、独立展开证据、Finding 编号块、Replay 边界说明、字号模式和响应式能力；
- 删除旧版的小字、技术字段前置、卡片套卡片和过长页面；
- 删除当前版本的冷白单调、图像水印化、结果首屏被首用区挤压、组件各自维护视觉变量等问题；
- 最终形成“浅色业务工作台 + 深色证据舞台”的统一界面，而不是深色全屏科技大屏或白色文档页面。

一句话设计原则：**评委先看懂结论，再看到证据；品牌美术负责建立记忆点，不负责遮盖内容。**

## 2. 审查范围与事实依据

### 2.1 已核对的内容

- 旧版视觉规范与相关功能文档：F-032、F-033、F-038、F-040、F-041、F-043、F-044、F-045、F-048、F-049、F-059、F-060、F-061、F-062；
- 旧版关键截图：Finding 总结、攻击链、Trace 事件和验收页面；
- 当前本地真实流程：首次进入 → 使用合成演示 → 运行安全检查 → Critical Finding；
- 当前设置与计划、扫描记录、验收证据等次级工作区；
- 当前 Web 端样式层、组件局部样式和美术资源引用方式；
- 桌面大字模式、移动端宽度、攻击链展开、控制台错误和横向溢出情况。

### 2.2 当前版本的优点

- 四个工作区比旧版更容易理解；
- 首次使用路径能够告诉用户下一步做什么；
- Critical Finding 已先给中文业务结论，不再只展示技术字段；
- 攻击链六个节点等高，单个证据展开不会拉长其他节点；
- Finding 编号已有独立标签位置；
- 技术详情默认折叠；
- Replay 明确是参考控制项模拟，不冒充企业根因结论；
- 标准/大字模式、窄屏布局和主要真实流程均可运行；
- 本次检查中未发现页面横向溢出或浏览器 console warning/error。

### 2.3 当前版本的主要问题

1. **品牌视觉被削弱。** 页面主要由白色、冷灰、细分割线组成，旧版的 navy、blue、teal、coral 只剩少量点缀。
2. **原有插图失去语义主角地位。** 有些被做成近乎透明的背景水印，有些被压成很窄的装饰条，无法承担 Finding、Replay、Provider 状态的解释作用。
3. **结果首屏优先级错误。** 完成安全检查后，首用路径仍占据结果上方较大空间；用户需要先经过“演示已完成”的重复说明，才看到真正风险结论。
4. **F-062 概念稿和实现结果不一致。** 概念稿依靠大字号、图标、留白节奏和强结果入口建立秩序；实现主要保留了白底、细线和低阴影，因而显得平、淡、缺少焦点。
5. **字号债务仍然很大。** `apps/web/src` 中仍有 486 处 `8px` 至 `13px` 的字号声明，技术页面尤其集中。大字模式不能替代默认字号治理。
6. **视觉规则重复。** 全局样式经历 F-032、F-061、F-062 多层覆盖，若干组件又维护 `--guided-editorial-*`、`--replay-editorial-*`、`--report-editorial-*` 等局部变量，容易产生同义不同色和 specificity 补丁。
7. **长页面仍然明显。** 验收证据与完整 Trace 默认包含大量事件和小字段，不适合比赛讲解节奏。
8. **移动端可点击尺寸不统一。** 抽样检查中仍有多处交互目标小于 44px。

### 2.4 旧版真正值得保留的部分

- 深 navy 品牌锚点与浅色业务空间的对比；
- blue 表示操作与过程、teal 表示通过与连通、coral 表示风险与阻断、amber 表示运行与等待的稳定语义；
- Finding、Replay、Provider Readiness、Acceptance 分别拥有状态对应的专用插图；
- 证据阶段具有明显层次和视觉焦点；
- 卡片、色带和阴影能够帮助快速分组；
- 缩小窗口时仍能保持产品辨识度。

旧版不应恢复的部分包括：8–12px 正文、默认展示 English ID、过多 mono 字体、卡片嵌套、整页科技背景、默认展开原始 JSON/Trace。

## 3. 目标视觉方向

### 3.1 核心构图

产品由三种视觉层组成：

1. **品牌层**：顶部品牌栏、启动页和少量关键入口使用深 navy；
2. **业务层**：任务选择、规则设置、文档和摘要使用浅色工作台；
3. **证据层**：攻击链、Critical Finding、Replay 对比和验收收口使用有边界的深色证据舞台。

深色只能用于品牌锚点和证据聚焦区，不铺满所有工作区；深色状态插图只能出现在真实业务状态对应的位置。旧版浅色网络图可作为低干扰环境底纹增强比赛观感，但不能成为独立内容块、抢占操作空间或降低文字对比度。

### 3.2 视觉节奏

- 每个页面只设置一个主标题和一个主操作；
- 首屏只回答三个问题：现在是什么状态、发现了什么、下一步做什么；
- 业务说明使用中文自然语言，技术 ID 放在次级行或折叠详情；
- 一屏内最多出现一个主插图焦点；
- 卡片只用于“可独立理解或操作的对象”，普通信息分组使用留白和分割线；
- 风险使用 coral 强调，不能使用低对比粉字叠粉底；
- 不用无意义发光、渐变文字、巨大圆角和漂浮装饰制造“科技感”。

## 4. 设计系统

### 4.1 色彩令牌

沿用 F-032 的品牌基础，并增加可访问性用途划分：

| 用途 | 建议值 | 使用规则 |
|---|---:|---|
| Brand Navy | `#0B2340` | 顶栏、证据舞台、深色品牌锚点 |
| Action Blue | `#4F7CFF` | 主按钮、当前步骤、可操作链接 |
| Evidence Teal | `#25BFAE` | 通过、连通、已验证证据 |
| Risk Coral | `#FF5D5D` | Critical、违规、阻断失败 |
| Warning Amber | `#E6A23C` | 运行中、待确认、警告 |
| Canvas | `#F4F7FB` | 页面背景 |
| Surface | `#FFFFFF` | 主要工作区和卡片 |
| Ink | `#132238` | 主正文和标题 |
| Muted | `#64748B` | 次级说明，不承载关键结论 |

实施时必须从实际背景计算对比度。正文和小标签不得仅因为“属于品牌色”而牺牲 WCAG AA 可读性。

### 4.2 字体层级

| 角色 | 标准模式 | 大字模式 | 说明 |
|---|---:|---:|---|
| 页面主标题 | 32px | 38px | 每页仅一个 |
| 区块标题 | 24px | 28px | 结果、攻击链、复测等 |
| 卡片标题 | 18px | 21px | 可独立对象标题 |
| 正文 | 16px | 18px | 默认业务文本 |
| 辅助文字 | 14px | 16px | 时间、说明、状态 |
| 标签/编号 | 12px | 14px | 只放短标签，不放长句 |
| Code/ID | 13px | 15px | 可换行、可复制、默认次级 |

规则：

- 不再新增 8–11px 可见文字；
- 12px 只能用于极短标签，不得承载错误原因、下一步或关键证据；
- 默认正文至少 16px，移动端不缩小正文；
- mono 字体只用于 ID、规则名、时间戳和原始数据；
- 长技术值必须允许按语义换行，不能在字符中间任意断开。

### 4.3 间距、圆角与阴影

- 间距使用 4/8/12/16/24/32/48 的统一序列；
- 主工作区最大宽度建议 1440px，比赛演示的主要叙事宽度控制在 1180–1320px；
- 普通卡片圆角 12px，强调证据舞台 16px，按钮 8–10px；
- 阴影只区分层级：普通卡片轻阴影，悬浮/对话框中阴影，禁止每个模块都浮起；
- 每个区块上下至少 32px，首屏信息不能被无效留白推到第二屏。

### 4.4 图标规范

- 使用同一套 SVG outline 图标，保持相同 stroke、端点和视觉尺寸；
- 图标只表示真实语义：连接、资料、规则、运行、风险、证据、复测；
- 当前使用的纯文本箭头、圆点和感叹号应替换为可访问的图标组件；
- 图标不能单独传递关键状态，必须配合文字或 `aria-label`；
- 不为装饰堆叠机器人、星光、魔法棒等泛 AI 符号。

### 4.5 动效规范

- 页面转场 160–220ms，强调状态 220–320ms；
- 运行中只允许 `evidence-pulse` 对应的轻微扫描动效；
- Finding 和 Replay 结果使用一次性淡入/位移，不循环闪烁；
- 支持 `prefers-reduced-motion`，关闭非必要动画。

## 6. 页面级重构方案

### 6.1 核心验收：首次进入

- 保留两条清晰路径：“使用合成演示”和“验收我的知识助手”；
- 使用浅色工作台并恢复 navy 品牌锚点；首次入口不放与当前选择无关的独立大幅装饰图，可保留旧版浅色网络环境底纹；视觉层级由排版、留白、对齐和任务控件建立；
- 路径卡提供对象、预计时间和结果，不重复解释底层技术；
- 在用户未选择路径、尚未完成第一次检查时显示完整首用区；
- 用户选定路径后，完整首用区收为步骤条；完成一次检查后，再收为 56–72px 的“当前路径/换一条路径”栏。

### 6.2 核心验收：Critical Finding

完成检查后，首屏顺序固定为：

1. 风险等级与一句中文结论；
2. “权限拒绝但动作仍执行”的因果说明；
3. 操作人、输入来源、工具动作、数据去向四个业务事实；
4. `finding-evidence-focus.webp` 风险视觉；
5. 主操作“运行模拟 Replay”；
6. 攻击链与进一步证据。

Finding 编号继续使用独立信息块，但放在次级位置；`finding_001` 不再叠在图片上。规则 ID、Scan ID、Attempt 和耗时移入“技术详情”。

### 6.3 攻击链

- 保留六个等高节点和独立证据抽屉；
- 用 `audit-chain-data-flow.webp` 恢复深色证据舞台，但节点本身保持高对比浅色表面；
- 默认只显示中文业务名、状态和一行解释；
- English technical name 放在证据展开或复制区域；
- 拒绝节点使用 coral 边框和图标，连通/已观测使用 teal；
- 节点之间箭头使用 SVG，并在窄屏改为纵向流；
- 证据展开不能改变其他节点高度，也不能把原始 JSON 直接塞进窄卡片。

### 6.4 Replay

- Before/After 使用两张原有配对插图，尺寸、裁切和信息结构完全对称；
- 先给“风险是否被阻断”的业务结论，再给差异字段；
- 明确“参考配置模拟”与“未修改企业系统”；
- 复测通过使用 teal，仍失败使用 coral，运行中使用 amber；
- 原始配置、参考配置和技术差异默认折叠。

### 6.5 设置与计划

- 保留连接、规则、资料三类任务，但避免把所有配置同时铺开；
- Provider 已连接时必须保留可发现的“查看/更改连接”入口；
- Provider 状态图恢复为清晰、有限高度的状态插图；
- Attack Plan 只有一个时展示静态摘要，不显示无意义 selector；多个时再显示选择器；
- Security Contract 首层使用角色、资源、动作、去向的中文解释，规则 ID 放次级层；
- 文档导入用明确空状态、成功状态和失败原因，不使用通用装饰图。

### 6.6 扫描记录

- 默认展示时间、目标、结果、风险数和可继续动作；
- Scan ID、Attempt ID、Provider/Model、Trace 数量作为次级元数据；
- 详情页先展示业务摘要，再按需展开 Trace；
- 长 Trace 使用分段、筛选或虚拟列表，不把全部事件同时铺在页面上。

### 6.7 验收证据

- 使用 `acceptance-evidence-convergence.webp` 作为证据汇聚主视觉；
- 首屏先回答：覆盖了什么、通过了什么、仍缺什么、证据在哪里；
- 将 Case、Replay、Differential、Release Gate 按业务分组，不呈现一个无限长的技术页面；
- 质量基准失败必须使用高对比错误块，错误原因与处理建议不低于 14px；
- 原始 acceptance、Trace 和导出字段进入折叠详情。

### 6.8 移动端与显示模式

- 390px 宽度无横向滚动；
- 触控目标至少 44×44px；
- 首屏风险结论、主操作和四个业务事实仍可直接看到；
- 攻击链纵向排列，箭头向下；
- 插图使用状态相关裁切，不隐藏关键焦点；
- 标准/大字模式共享同一排版系统，不能依靠大字模式修复标准模式的小字。

## 8. 分阶段实施

### Phase 0：冻结基准

交付物：

- 保存当前关键状态截图和 DOM/交互基准；
- 登记现有 E2E、测试选择器和必须保留的 F-059 至 F-062 行为；
- 建立“旧版资源 → 当前状态 → 目标位置”的视觉对照表；
- 记录现存功能失败，不在视觉修改中掩盖。

退出条件：所有将被修改的页面均有桌面和移动端基准图，业务行为清单获得确认。

### Phase 1：概念定稿

先制作并审查三张静态概念稿：

1. 首次进入桌面版；
2. Critical Finding 桌面版；
3. Critical Finding 390px 移动版。

概念稿必须使用真实页面文案，不允许用假数据或重新生成风格不一致的插图。现有深色状态美术只在与真实运行或证据状态直接对应时复用；浅色网络图可作低干扰环境装饰，但首次入口不为填充版面放置独立无语义图片块。

退出条件：确认色彩、图片占比、卡片密度、首屏顺序和移动端结构后才进入代码。

### Phase 2：设计系统与基础组件

- 合并颜色、排版、间距、圆角、阴影和状态 token；
- 建立 Page Header、Result Hero、Evidence Stage、Status Banner、Metric、Details、Empty/Error State 等基础结构；
- 建立统一 SVG Icon 组件；
- 先解决全局字号与交互尺寸，不做页面局部美化。

退出条件：设计 token 在标准/大字、桌面/移动端均可复用；无重复页面私有色盘。

### Phase 3：核心演示链路

- 首次使用；
- 合成演示；
- Critical Finding；
- 攻击链；
- Replay。

按垂直切片逐页替换，每完成一页立即运行真实流程和截图对比，不等待全部页面结束再验收。

退出条件：评委可在 5 分钟内完成一次真实检查，并在每个首屏直接说出“发生了什么、证据是什么、下一步是什么”。

### Phase 4：次级工作区

- Provider 连接与就绪；
- 规则与计划；
- 文档导入；
- 扫描记录；
- 验收证据。

退出条件：所有工作区使用相同设计系统，技术详情默认折叠，主要错误均提供原因与下一步。

### Phase 5：无障碍与响应式收口

- 对比度、键盘焦点、44px 触控目标；
- 390px 移动端；
- 标准/大字模式；
- reduced motion；
- 长中文、长 ID、错误消息和空状态。

退出条件：目标视口无横向溢出、无遮挡、无不可辨识小字。

### Phase 6：完整回归与发行验证

- Web typecheck/build；
- 相关 Python/集成测试；
- 全量 Playwright E2E；
- Windows 安装包实际运行复核；
- 关键页面逐张视觉审查。

退出条件：功能、视觉、响应式和安装版证据同时闭合后，才可将 F-063 标记完成。

## 9. 视觉与交互验收矩阵

### 9.1 视口

- 1280×800：普通笔记本最低演示尺寸；
- 1440×900：主要开发基准；
- 1600×1000：大字模式基准；
- 1920×1080：答辩投屏基准；
- 390×844：移动端基准。

### 9.2 状态

- 未选择首用路径；
- Demo 路径已选择但未运行；
- Provider 未就绪、已就绪、连接失败；
- 文档为空、导入中、导入成功、导入失败；
- 扫描 idle、loading、Critical、passed、error；
- 攻击链默认与任一证据展开；
- Replay running、passed、failed；
- 扫描记录空态与详情；
- 验收证据 empty、running、success、error；
- 启动失败页。

### 9.3 每个状态的硬性检查

- 第一屏能看到状态、结论和主操作；
- 无横向溢出或中间字符断行；
- 正文与状态对比度达到 WCAG AA；
- 可点击目标至少 44×44px；
- 业务正文不小于 16px，辅助文字不小于 14px；
- 图片与真实状态一致，不能用 success 图表达未验证状态；
- 技术 ID 与 JSON 默认不抢占主层；
- 标准/大字模式均保持层次；
- 键盘焦点可见，图标具有文字替代；
- 浏览器 console 无新增 warning/error。

## 10. 测试与证据计划

### 10.1 自动化保护

- 保留 F-059 至 F-062 已验证的业务交互与语义测试；
- 对 F-062 中只用于锁定已否定白色视觉方向的断言，在新概念获批后按新规范更新，不能机械保留；
- 新增“完成检查后首用区折叠、结果进入首屏”的 E2E；
- 新增插图与业务状态映射测试；
- 保留攻击链等高、独立证据展开、单/多 Attack Plan、Finding ID 独立块、固定 Case 按钮对齐等回归；
- 新增 390px 无横向溢出和 44px 触控目标检查；
- 对主要前景/背景组合做自动对比度检查；
- 对关键页面做固定视口截图基准，但只锁定结构和关键区域，不锁定易波动的运行 ID/时间。

### 10.2 人工审查

- 每个 Phase 至少进行一次旧版、当前版、目标版三列对照；
- 由非开发人员用一句话复述每个首屏；若先解释字段含义才能看懂，则视为未通过；
- 使用真实安装版复核字体、缩放、关闭行为和资源加载，开发服务器截图不能代替安装版证据。

### 10.3 并行功能债务

当前质量基准/完整 acceptance 的本地真实路径可能出现：

`mock_mail_send resourceIds must come from model_context`

该问题属于功能证据债务，应单独定位和修复。视觉重构只能改善错误的解释与呈现，不得吞掉、伪装或改写真实失败结果。

## 11. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 工作树包含大量未提交改动 | 不做全量回滚；逐组件迁移并在每步核对 diff |
| 旧版视觉恢复时带回小字和技术感 | 视觉资源与信息结构分离；执行新的字号和内容分层规则 |
| CSS specificity 继续叠加 | 先建立 token/基础组件，再删除旧覆盖层，不新增 `!important` 补丁体系 |
| 插图导致加载或裁切问题 | 使用现有 WebP，按状态懒加载，固定 aspect-ratio 和焦点位置 |
| 截图测试把错误视觉固化 | 先确认三张概念稿，再更新视觉基准 |
| 比赛表达和工程视图互相冲突 | 业务层默认可读，技术层可展开；不删除真实证据 |
| 视觉修改误伤 API/审计语义 | 不改变 contracts、Finding 判断、Trace、Replay 和 acceptance 业务语义 |

## 12. 完成定义

F-063 只有同时满足以下条件才可完成：

- 旧版品牌色和原有状态美术恢复为可辨识、语义正确的视觉系统；
- 当前版本的中文业务表达、四工作区、攻击链等高、独立证据和 Replay 边界全部保留；
- 完成检查后，风险结果成为首屏主体；
- 不再存在关键错误、下一步或证据说明使用 8–12px 小字；
- 桌面、投屏、大字和 390px 移动端均通过验收矩阵；
- 关键图片不再被当作全局低透明度水印；
- Web build、相关集成测试和全量 E2E 通过；
- 真实安装版完成一次关键流程视觉复核；
- 文档、截图和实际代码状态一致。

## 13. 非目标

本计划不包括：

- 修改 Security Contract、Finding、Trace、Replay 或 Acceptance 的业务判定；
- 新增真实企业 Gateway、真实邮件、真实敏感数据或外部目标扫描；
- 为了视觉演示伪造通过状态、假数据或假证据；
- 重做启动页品牌图；
- 生成比赛 PPT、Word 或 PDF；
- 在概念未确认前直接进行全站 CSS 重写。
